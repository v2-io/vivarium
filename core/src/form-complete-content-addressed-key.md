# Complete content-addressed key

Every memo is keyed by everything that affects it; an incomplete key is silent corruption, so over-key never under-key.

## Formal Expression

1. **Complete key.** A #lexicon/term/memo is addressed by a content key that folds in *everything that affects the value*: upstream input identities (hashes), coupling parameters, seed, and the producing #lexicon/term/nomos's identity and version (plus resolution, time, and other coordinates when they change the bytes). Omitting an input that changes the output is under-keying.
2. **Asymmetry.** Under-keying serves a stale memo that *lies* (silent corruption). Over-keying costs only recompute. When the choice is forced: **over-key.**
3. **Key, never caution.** Memoization must not be "kept safe" by disabling the cache while iterating, by manual cache-clear as a workflow step, or by deferring caching until algorithms "settle." The only lawful mechanism that keeps memoization from interfering with iteration is a complete key. (Joseph, 2026-07-09 pervasive-memoization directive — carried in design source; the over-key cost asymmetry itself is the correctness trade, not a separate named decision.)
4. **Nomos version participates.** Algorithm identity is part of the key ( #lexicon/term/generator-pinning — open as a term, practice already assumed). Every world-law key stem folds in a **build-time whole-crate source digest** (`build.rs` hashes every `.rs` file in `vivarium-world/src`, injected as `VIVARIUM_SRC_HASH`, folded by `NomosDecl::key`), so a kernel edit invalidates its memos whether or not the hand-stamped version string was bumped — human bump-discipline is no longer load-bearing for correctness. The digest is coarse by design: whole-crate covers transitive in-crate deps with no hand-maintained source→nomos map (over-key is the safe direction, FE(2)); the hand-stamped `version` remains as the human-legible algorithm era. Optional IR-normalized hashing and finer per-nomos attribution are non-dogmatic tightening, not settled law.
5. **Determinism is the precondition.** Memoization is sound only because law and aleatoric detail are pure functions of keyed inputs ( #post-determinism-as-ontology , #lexicon/term/fated-noise ). Unkeyed entropy makes every key incomplete by construction.

6. **A key holds a descriptor, never a payload — completeness is about *denotation*, not about size.** Folding a **name that determines** an input is exactly as complete as folding that input's bytes, because under FE(5) the name and the value are in bijection. This is not a relaxation; it is what the practice has always been. `query::erosion_key` folds $(\text{seed}, \text{face}, \text{level}, o_i, o_j, n_x, \text{epochs})$ plus each dependency's *name and version* (`Key::with_dep_versions` writes `name=version` pairs) and never the content hash of the initial-topography, uplift or climate tiles it consumes — those coordinates and versions determine those tiles, so the key denotes them completely at constant size.

   The consequence is worth stating because its absence produces a specific false obstruction: **a nomos whose value depends on its neighbours does not thereby need its neighbours in its key.** It needs whatever names them — a schedule descriptor from which the neighbour set is a function of its own coordinates — and the recursion that reaches through them terminates wherever the dependency chain does. The transitive **dependency cone** is real and is a scheduling and cost fact; the **key payload** stays $O(1)$. Reasoning that a cross-tile dependency "closes over the whole planet" conflates the two, and the conflation blocks designs that key perfectly well ( #form-same-level-halo-exchange FE(4) is the worked instance). What the name must still fold is every field that *changes* the denotation — a halo depth, an exchange cadence, a contract, a truncation radius are all identity the moment a caller can vary them, and omitting one is ordinary under-keying (FE(1)).

## Epistemic Status

**Max attainable: exact** as architecture **law** under determinism-as-ontology. The law is falsified if we treat an incomplete key as complete, or treat cache-disable / manual flush as the iteration safety valve. **Present practice can under-key without falsifying the law** — that is compliance debt, not a warrant to soften the claim (strengthen-before-soften: fix the keys and the guards first).

**Known incomplete surfaces (compliance and MVP debt; not a soften of the law):**

1. **64-bit FNV-1a is not collision-safe at scale.** The store's content hash is MVP-grade FNV-1a; the module docs state it is fine for demo object counts and **not** collision-safe at scale. Replacing it before the store holds unrecomputable artifacts is named engineering advice in code — **not** a DECISIONS entry. Do not treat BLAKE3 (or any specific successor hash) as decided unless and until DECISIONS records it. (The build-time *source* digest reuses FNV-1a as a change-detector over our own source, where collision-resistance is not the property at stake — distinct from the store's content hash.)
2. **Completeness is doctrine more than full enforcement.** Under-keying is the named unsafe failure. Nomotheke pins consumed⇒in-deps and dep-identity-in-key; the build-time source digest closes the forgotten-version-bump path. Live under-keying (e.g. a dynamic input omitted from a key so a change serves stale hits) is a **bug against this law**, not evidence the law is wrong.
3. **Source-digest granularity is the coarse floor, and finer attribution is a measured no-go at present code structure.** The build-time digest is whole-crate: editing any `.rs` (including a comment or a test) invalidates the whole store — over-keying, the safe direction. **Attribution granularity cannot exceed *code* granularity, and this crate is not partitioned by nomos.** Two independent obstructions, both measured 2026-07-24: (a) *correctness* — `deps` is itself hand-maintained and under-covers, so declaration-derived attribution under-keys, the unsafe direction. `MANTLE_THERMAL.deps` is empty while `query::epoch_reduction_key` mints from it over a computation spanning `sea_level`, `erosion_return`, `lithosphere`, `gen` and `hydrosphere`; changing one constant in `sea_level.rs` moves `derived_sea_m` on every epoch while a digest scoped to `mantle_thermal.rs` stays bit-identical, so six roots would Hit and serve a wrong sea level silently. (`climate.rs` calls `noise::fbm` with `NOISE` absent from `CLIMATE.deps`; `query.rs`, where tiles are computed, belongs to no nomos.) Root cause is #form-nomotheke-registry Known-incomplete (2), open. (b) *payoff* — even the compiler-safe form, attribution derived from the `crate::` module graph with no map anywhere, spares **zero** of 39 sampled commits entirely and saves **0 %** on the four most-edited files; module closures reach 17–26 of 33 modules and two dependency cycles exist. **The unblock condition is therefore module *separation*, not attribution *derivability*** — a sharper and checkable signpost, and one the earlier wording missed. Narrowings that need no attribution (excluding `src/bin/`, which Cargo guarantees the lib cannot reference; normalising comments out of the digest) are admissible and address the papercut, not the workflow.

## Discussion

This is one of the three walls that keep parallel system work and fidelity-ladder swaps cache-transparent: change a nomos **version** and exactly its dependent cone invalidates. That cone property holds for the *declared* version component; it does **not** hold for the *source* component, which is whole-crate by Known-incomplete (3) — so a source edit invalidates everything, and iteration on kernels does not preserve the rest of the store. Stating the cone property unqualified reads as shipped and is not; the honest reading is that key completeness is exact and key *narrowness* is bounded by code structure. Scratch and canon can share one object store because different keys never collide by construction. Sibling store claims (save-file *is* the memo store; pervasive disk memoization as economic default; run-mode root discipline) are not this segment — they need their own homes. Generator-pinning is the dictionary face of version-in-key; this segment is the completeness law those pins serve.
