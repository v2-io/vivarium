## The one real finding: a stale summary sentence in `disc-known-active-hotspots.md`

`core/src/disc-known-active-hotspots.md` line 102, in the **Epistemic Status** section:

> "Leverage rank (FE(5)) and molten table (FE(6)) dated **2026-07-29**, revised after halo **adoption** (builder/view ship Jacobi; **rank 1 is water settle**; 1b flux/spill)."

This is wrong twice over. The FE(5) leverage table itself was correctly revised **twice** in this range:

1. `5e9fa69` (2026-07-29 late evening) re-ranked rank 1 to "stop the reader computing across tiers" (the mixed-tier surface problem) and *demoted* "water settle" to the demote row, with a "Superseded rank table" kept alongside for comparison.
2. `8fb85e5` (2026-07-30, the second-to-last commit in this range) marked that rank-1 row `**done**` and promoted a *new* rank 1: "Phase-3 gate predicates that can fail."

So as of `HEAD`, current rank 1 is the phase-3-gate-predicates item. The Epistemic Status sentence, however, was written for neither revision — it says "rank 1 is water settle," which was already superseded *before* `5e9fa69` landed (that commit's own superseded-table caption calls it "2026-07-29, earlier"). Commit `8fb85e5`'s own message says "Hotspots: rank 1 retired as done. New rank 1 is the phase-3 gate predicates" — the author knew the table changed and edited the table, but the Epistemic Status summary one section down was not touched in either pass.

This matters because Epistemic Status is exactly the section `FORMAT.md` §4 tells a reader to trust for "what work is still expected on this segment now" — a reader who reads that line instead of the full FE(5) table (which is long, and the segment itself warns tables like this are easy to skim) will walk away believing water-settle is still the top-ranked item, which is the one thing this session spent the most effort establishing is *no longer true* (`#form-ocean-is-connectivity-not-elevation` exists specifically to show lakes didn't need the settle).

**Fix would be a one-line edit** — I did not make it, per the brief.

## What I could not verify, and said so rather than guessing

- **Verbatim Joseph quotes** inside `DECISIONS.decision-log.udon` and several commit messages ("No phantom holographic world layers...", "fine details block water. period.", "I wouldn't shy away from doing things right just because it feels risky...") — I have no transcript to check these against. This is true of essentially all such quotes in this repo's history and isn't specific to tonight's work; I'm flagging it as a category of unverifiable-by-me claim rather than as a finding, since nothing about how they're used here looks off (they're used for exactly the kind of "he said this, here's why it's law" attribution the decision-log format exists for).
- **FE(6)'s rebuild-diff table** in `#obs-connectivity-fills-the-basins-the-threshold-drained` (erosion-tile 1065/3552 changed, beacon 452/28, water-tile 384/0) describes a rebuild the store has since moved past twice more, so I can't re-derive it from the live store the way I could the more recent numbers. It's internally consistent with the commit message and with the DECISIONS entry that cites the same figures, which is the best corroboration available short of a transcript.
- **The 88% figure** ("carving destroys 88% of the prior's basins") is stated in FE(5)/Discussion but is a derived characterization rather than a probe-printed number; the printed numbers it's built from (`210`/`26` vs `1780`/`59`) I did verify directly, and `1 - 210/1780 = 0.882`, so the arithmetic is right, but the word "destroys" (versus, say, "consolidates" — several small prior basins might merge into fewer, larger carved ones rather than vanishing) is an interpretive gloss on a cell-count ratio. I don't think this rises to misleading — the segment is explicit that this is drainage integration doing its work — but it's the one place I'd call a characterization rather than a measurement, worth knowing if it gets quoted elsewhere as a hard number.
